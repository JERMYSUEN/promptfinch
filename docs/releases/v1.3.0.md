# PromptFinch v1.3.0

This release changes prompt editing and adds an optional, bounded model-assisted fidelity review. Windows/Linux remain desktop previews with the selection limitations documented in the [desktop guide](../desktop.md). macOS remains the native Swift app.

## Downloads and setup

Download the package for your system from [v1.3.0](https://github.com/JERMYSUEN/promptfinch/releases/tag/v1.3.0):

| System | Package | Runtime |
| --- | --- | --- |
| Windows x64 | `PromptFinch-1.3.0-windows-x64-setup.exe` or `PromptFinch-1.3.0-windows-x64.zip` | Included |
| Linux x64 | `PromptFinch-1.3.0-linux-x64.AppImage` or `PromptFinch-1.3.0-linux-x64.tar.gz` | Included; compatible host libraries still required |
| macOS Apple Silicon | `PromptFinch-1.3.0-macos-arm64.zip` | Install Node.js 22+ separately |
| Source | `PromptFinch-source-v1.3.0.zip` | Node.js 22.12+ for desktop development |

The matching checksum files and build/verification manifests accompany the packages. Packages remain unsigned or ad-hoc signed, without Windows publisher signing or Apple notarization. Linux builds target Ubuntu 22.04 x86_64-compatible glibc distributions; X11 selection is experimental and Wayland uses manual input/clipboard import. Windows Chromium/Electron selection, including Codex/Claude, remains unverified. ARM64 Windows/Linux and physical installer/host-app acceptance are not covered.

On macOS, installation preserves a separately selected external backend. To adopt this release's bundled optimizer, use **Settings → Use this app's bundled backend** after installing it. That action retains the selected private model configuration and attempts rollback on failure. See the [native upgrade guide](../macos.md).

## Editing behavior

English and Traditional Chinese now use one editing policy and each return a complete task prompt. Traditional Chinese live output no longer appends the original instructions as a reference wrapper; required source documents/data/literals must be included in the rewritten task itself. API clients that parse wrapper headings must migrate to using the complete `prompt` field. Input/output comparison still retains the source snapshot separately.

The rules address missing versus insufficient inputs, conditional instructions, no-question restrictions, source/tool access, conflicts and compatible fallback formatting. Prompt instruction language, task-answer language and notes language remain separate. Already clear requests may return `improvements: []`; the interface reports that no editing notes were provided without claiming a nonexistent improvement. Exact Unicode literal restoration handles contractions, repeated copies and conservative ambiguity checks in both instruction modes.

## Model review, latency and cost

Additional review is disabled by default. Set `LLM_QUALITY_REVIEW=true` in the private model file to enable it. The same configured provider/model receives the original and candidate in a separate review context. A rejected candidate gets at most one revision. A second rejection or malformed review returns an error instead of an unreviewed/partial candidate. Editor, review and revision calls share the original `LLM_TIMEOUT_MS` deadline and cancellation signal.

When review is enabled, a normal successful request makes two provider calls. At most four are permitted, including format retries and a bounded revision/review. This adds latency and paid token usage. The default path retains the one/two-editor-attempt behavior; `LLM_QUALITY_REVIEW=false` also selects that path. Mock mode makes no provider calls and does not translate or optimize. No additional model service or fallback key is introduced.

`modelReview.status: "approved"` records that model's judgment; it is not an independent correctness certificate. The [comparison record](../prompt-quality-verification.md) retains unsuccessful experiments and remaining semantic errors. Review important requirements against the source before use. No downstream writing/coding/analysis task performance improvement is claimed.

## Validation and previous releases

The [quality rubric](../prompt-quality-rubric.md), controlled tests, live synthetic records and independent Codex review cover different evidence. The [API reference](../api.md) describes the response metadata and configuration. Desktop CI builds and tests development/packaged mock workspaces on native Windows/Linux hosts; public Mac/source checks validate their delivered archives and isolated mock HTTP.

The `v1.0.0`, `v1.1.0` and `v1.2.0` tags and assets retain their original contents. There is no automatic updater.
