# PromptFinch v1.2.0

This release adds Windows x64 and Linux x64 desktop previews. The macOS edition remains the native Swift app. The existing browser workspace, HTTP API and model policy are unchanged.

Windows/Linux packages have separate `SHA256SUMS-<platform>-x64.txt` and build manifests; `SHA256SUMS` covers the macOS/source set. Packages are unsigned or ad-hoc signed, without Windows publisher signing or Apple notarization. No automatic updater is included.

Linux packages are built/tested on Ubuntu 22.04 x86_64 for compatible glibc-based distributions. Host libraries are still required; older distributions and Alpine/musl are unverified. The Linux AppImage needs executable permission and can require FUSE 2. The tarball provides an alternative. Keep the runtime and sandbox files together; run as a normal user. See the [desktop installation guide](../desktop.md) for build requirements and launch details. macOS setup and upgrade behavior remain in the [native guide](../macos.md).

## Desktop workflow

The Windows/Linux workspace includes Traditional Chinese, English, Japanese and Korean interfaces; six task types; an optional target-model hint; copyable English prompts; editing notes; assumptions; source comparison; cancellation; and clear actions. It does not paste or submit text automatically to any source app or terminal.

On Windows UI Automation and Linux X11, a right-click can show a separate PromptFinch companion beside the original context menu. It includes a local preview and conversion/cancel actions. Right-clicking alone does not call a model. The captured text expires after ten seconds. Windows verifies the foreground source before generation; X11 rechecks the selection text. Input and results are not saved as history.

This selection feature is experimental. Windows requires an accessible selected range from the source app. A passing synthetic native/Chromium fixture with Chromium native UIA explicitly enabled does not certify Windows Codex, Claude, terminal or remote-desktop compatibility. X11 PRIMARY selections can outlive highlighting; inspect the preview before conversion. Wayland has no global right-click observer in this release; use manual input or copy and import the clipboard. ARM64 Windows/Linux and physical desktop installation checks are not covered by the x64 builds.

`Ctrl+Alt+P` imports a selection where supported. `Ctrl+Alt+Shift+P` imports copied text. These shortcuts do not generate and can conflict with desktop/app shortcuts. Settings displays availability. On Windows, use external right-click/shortcut capture rather than clicking a workspace button that would change source focus.

## Model configuration and privacy

A new desktop profile starts in clearly marked mock mode. Mock output adds a fixed wrapper; it does not translate or optimize. In Settings, create a private configuration template, fill in your provider key and model, then select that file. The app reads credentials only in its main process. Invalid live settings block generation instead of substituting a mock result. A Codex/Claude login is not a provider API key.

The renderer is sandboxed, has no Node access, accepts only fixed IPC operations and loads local allowlisted assets. Model calls use the existing optimizer in the main process, without an HTTP listener. Preferences store the interface language and selected configuration path, not keys or prompts. The Windows observer caches a single focused control reference and basic metadata, and reads selected text only after a right-click or explicit capture request. The X11 helper observes right-button coordinates/time; the main process reads the selection locally. Content reaches the configured provider only after an explicit conversion/generation action.

## Verification scope

The [desktop workflow](../../.github/workflows/desktop.yml) builds on native Windows and Linux x64 runners. It checks source syntax, shared/desktop unit tests, Windows synthetic native and isolated Chromium selections with the UiaProvider feature explicitly enabled, X11 right-click observation and left-click exclusion, Wayland refusal, and development/packaged mock workspaces. Each desktop manifest records the exact commit, workflow run, platform, file sizes and SHA-256 hashes. The macOS Electron smoke check validates the shared desktop shell as a development aid; the macOS download is the separate Swift app.

The native Mac updater's atomic POSIX symlink replacement test is explicitly skipped on Windows because the Windows desktop does not use that updater. Its other shared tests still run. Native Swift checks, public source/app archive checks, browser checks and isolated mock HTTP remain separate validations.

No new live-provider quality evaluation is included. The existing [model verification](../improvement-verification.md) and its remaining semantic errors still apply. Automated helper tests do not replace physical mouse, display-scaling, installer, compositor and host-app acceptance checks. The [desktop guide](../desktop.md) lists the platform limits.
