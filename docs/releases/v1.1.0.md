# PromptFinch v1.1.0 — Safer updates, multilingual review and Terminal selections

PromptFinch turns rough requirements into clearer prompts for writing, coding, research, summarization and planning. It edits the instructions; it does not perform the original task. This release includes the changes made after the original v1.0.0 snapshot.

## What changed

- **Safer native lifecycle and installation:** backend responses must identify the exact owned process. Backend termination is asynchronous and bounded, including shutdown; installation validates a complete staged bundle before closing the old app and restores the previous bundle on a failed replacement.
- **Review in your language:** new improvement and assumption notes follow the native interface language, with a separate selector in the browser. `notesLanguage` accepts `zh-TW`, `en`, `ja`, and `ko`; the API default stays `zh-TW`. The English prompt and the task's answer language are independent.
- **Source/result comparison:** view the source snapshot used for a result and whole-line text changes. Editing the workspace later does not rewrite that snapshot. Comparison annotations never enter copied text.
- **Conflict and timeout handling:** Traditional Chinese source text is reference data when requirements conflict, rather than overriding conflict-resolution guidance. Provider retries share one total timeout budget.
- **Verified public packages:** the public packaging command creates source/App ZIPs, a source-input manifest and `SHA256SUMS`. Verification extracts the actual ZIPs and checks their contents, metadata and mock HTTP behavior. These checks are also included in CI.

- **Terminal selection support:** select readable text in macOS Terminal, right-click, then choose **Convert to English prompt** in PromptFinch's separate companion menu. Recognized terminal sources receive copy-only results: review the prompt, paste it into the intended CLI input yourself, and submit it yourself. The app does not treat a terminal's highlighted screen text as an editable input range.
- **Task editing beyond translation:** the model instructions now ask for clearer goals, relevant constraints, useful execution order and appropriate verification when the task needs them. Already-clear requests can stay short. These rules are intended to preserve the original purpose rather than add features, facts, formats or deliverables.
- **Multilingual editing rules:** English-mode metadata and examples address answer-language inference, supplied facts, conditional requirements, romanized instructions, exact literals and mixed-language input. New shared-task fixtures cover 29 locales / 28 languages, with separate language-edge cases and a runner that reports missing required literals.
- **A Codex workflow illustration:** the README shows selection, the companion action menu, result review and paste-back in a recreated Codex interface. The GIF and its example output are hand-authored synthetic content, not a real recording, a model response or evidence of model quality.
- **Clearer setup and troubleshooting documentation:** the guides now explain model settings, terminal limits, local backend updates, data handling and the scope of dated verification records. The release/package and native app versions are aligned at **1.1.0**, build **12**.

Existing workflows remain available: the native manual workspace, selection button, supported macOS Services, **⌥⌘P**, explicit clipboard input, and the optional browser workspace / HTTP API. A right-click alone does not call the model. Paste-back in compatible editable fields depends on verified selection access and the user's settings; it does not submit a chat message.

The app targets **macOS 13 or later** and requires **Node.js 22 or later**. The app includes backend source, not the Node runtime or a language model. If Node is not discovered automatically, select the Node executable in Settings. Live use requires your own compatible model API account, key and configuration; a Claude/Codex login does not supply these credentials.

The attached app is **Apple Silicon only**, not a Universal Binary. Intel users can attempt a source build on their own Mac, but an Intel build and minimum-supported-macOS device test have not been completed for this release. Compatibility also depends on each source application's Accessibility support.

This is **not a Developer ID-signed or notarized distribution**. macOS may block an untrusted download. Assess the source and use macOS's own security controls if you choose to run it; a source build is another option. Personal local signing supports update continuity on your own machine and does not establish public publisher trust.

## Install and configure

For a first installation, extract the app ZIP, move `PromptFinch.app` to your Applications folder, and install Node.js 22+ separately. Open the app and use Settings to choose Node if needed. Try the clearly labeled demo mode first, or select/create a private model configuration file for live use. Demo mode checks the interface without translation or semantic optimization.

Live configuration uses `OPTIMIZER_MODE=live`, `LLM_API_KEY`, `LLM_MODEL` and a compatible `LLM_BASE_URL`. The server appends `/chat/completions` to the base URL. The optional target-model field guides the prompt wording; it does not switch the configured generation model. Never put an API key into a prompt or a public report.

Cross-app selections need **System Settings → Privacy & Security → Accessibility** permission. The manual workspace and explicit clipboard input remain usable without cross-app selection permission. To review every editable-field result before replacement, turn off automatic paste-back in Settings. Recognized terminal sources always use copy-only delivery.

For upgrades, quit the old app before moving the new app into place. Replacing the app retains the existing external backend. In the new app, choose **Settings → Use this app’s bundled backend** to adopt its bundled rules. The action stages and verifies the bundle, restarts only its own service, and attempts rollback on failure. It retains your private model configuration, Node path and preferences. A source build can still use `npm run update:mac-backend` for a separately trusted backend update. Changing from a personal local signature to this ad-hoc download can require granting Accessibility again. Do not delete the whole `PromptSelection` support folder; it may contain private configuration and signing settings.

## Build the release source

Source builds require Node.js 22+, a supported Mac and Apple's Xcode Command Line Tools. No runtime `npm install` is needed; use `npm ci` for development/browser-test dependencies.

```sh
git clone --branch v1.1.0 https://github.com/JERMYSUEN/promptfinch.git
cd promptfinch
xcode-select --install  # Skip if already installed.
npm run setup:signing:mac  # Optional personal local signing identity.
npm run build:mac
npm run install:mac
```

`install:mac` installs and opens an existing build; it does not compile it. See the [macOS guide](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/macos.md) for settings, permissions and backend updates, the [Terminal guide](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/terminal.md) for CLI selection behavior, and the [documentation index](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/README.md) for browser/API use and troubleshooting.

## Verification and known limits

JavaScript syntax and 28 localized README checks passed. The Node suite passed 80 tests, the native suite passed 318 checks, and Chrome passed 11 browser tests. Public packaging verified the arm64 app, macOS 13.0 target, strict ad-hoc signature, backend ID, public source-input hashes, blank credential templates and archive allowlists; extracted source/App backend mock startup also passed. SHA256SUMS covers the app ZIP, source ZIP and verification manifest. See the [complete improvement record](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/improvement-verification.md) for scope and remaining issues.

The terminal companion menu and generation were confirmed by a user's physical-mouse test in Apple Terminal. That report did not independently identify Claude Code and Codex CLI versions or complete every clipboard, cancellation and manual-paste check. Automated checks do not establish compatibility with every terminal or editor.

The historical task-guidance requests failed with HTTP 502/504. A later refinement recorded 16 successful synthetic model responses and passing listed literal checks, with English/Traditional Chinese instructions and notes in four languages. Manual review still found wrong assumption labels, an omitted clarification condition and awkward conflict wording. This is a comparison of two preparation policies, not a v1.0.0 or downstream-task performance benchmark. Earlier multilingual results cover their own backend revisions and include remaining semantic errors. Neither valid JSON nor passing literal checks proves semantic fidelity or that every language matches Chinese output quality. Review generated prompts before use. See the [task-optimization record](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/optimization-value-verification.md) and [multilingual record](https://github.com/JERMYSUEN/promptfinch/blob/v1.1.0/docs/multilingual-parity-verification.md).

The native interface supports Traditional Chinese, English, Japanese and Korean; the browser interface is Traditional Chinese. Documentation translations and interface languages are separate from model-quality coverage. New improvement notes and assumptions follow the selected notes language. Existing results are not rewritten; model adherence remains subject to semantic review.

The original **v1.0.0 tag and download remain unchanged**. This is a new version, not a replacement of the old snapshot. PromptFinch is MIT licensed; model usage is billed by the user's provider.
