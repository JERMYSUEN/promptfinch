# 右鍵改為明確點選操作

日期：2026-10-09。使用者回報舊版Claude也可用，但在瀏覽器普通選取、右鍵時容易誤觸轉換。本次只調整原生右鍵入口，不改模型、優化規則或API設定。

## 新流程

選取文字 → 右鍵 → 游標旁的附加操作選單 → 點「轉為英文 Prompt」 → 核對選取 → 原有英文結果浮窗及貼回流程。

- 右鍵本身只顯示「轉為英文 Prompt／取消」，不生成、不傳送原文至模型，也不寫入剪貼簿。
- 原軟體的複製、搜尋等右鍵功能仍保留；助手沒有將項目插入原選單。附加選單是獨立的AppKit非啟用面板，顯示來源為「Prompt 選取助手」。
- 只有明確點選轉換後才關閉來源選單，並重新核對前景程序、欄位、選取文字與範圍。失配或無法核對會提示重新選取，不呼叫模型。
- 取消、點別處、鍵盤輸入、切換App及12秒逾時都作廢待選操作；同一選單操作只能執行一次。關閉右鍵功能或生成中亦拒絕轉換。
- 左鍵浮動按鈕、快捷鍵、Services與明確的剪貼簿入口沿用原行為。右鍵偏好沿用既有設定鍵，已啟用者自動改成選單方式；設定文字已更新，不需重新設定金鑰或權限。

來源App自行建立右鍵選單；例如[Electron官方文件](https://www.electronjs.org/docs/latest/tutorial/context-menu)說明其右鍵選單及Services的建立方式。本次採附加面板保持原選單功能，沒有修改Codex、Claude或瀏覽器的程式。

## 核對方式

1. 用實體滑鼠在瀏覽器或IDE選取測試文字，按右鍵；確認原選單保留且沒有載入／生成。
2. 使用原選單複製，或在附加選單按取消；確認沒有生成。
3. 再次選取、右鍵、點一次轉換；確認結果浮窗與模型模式。保留原文字中的答案語言及限制。
4. 在附加選單開啟後改選文字、切換App或等待超過12秒；舊操作不能送出。生成後複製／貼回／取消仍依原操作核對。

手動步驟3在live模式可能產生模型費用；可另選明示mock配置檢查結果顯示，mock不能作為英文翻譯品質證據。
